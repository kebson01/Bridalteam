# Content-Security-Policy (M4)

A nonce-based CSP is set in `middleware.ts`. It ships **Report-Only** so it
cannot break the site; you enforce it after verifying reports are clean.

## How it works

- Each request gets a random `nonce`. `script-src` is
  `'self' 'nonce-<nonce>' 'strict-dynamic'`, so only Next's own (nonced) scripts
  and what they load can execute — an injected inline `<script>` from any XSS in
  user content (comments, community posts) is blocked. Next reads the nonce from
  the CSP request header and stamps it onto the scripts it renders.
- `connect-src` allows the Supabase REST API and realtime websocket. Anthropic is
  called server-side only, so it is intentionally **not** listed.
- `style-src` keeps `'unsafe-inline'` (Next/Tailwind inline styles; style
  injection is far lower risk than script injection).

## Env flags

| Var | Default | Effect |
|-----|---------|--------|
| `CSP_ENFORCE` | unset | `true` → send enforcing `Content-Security-Policy`. Anything else → `Content-Security-Policy-Report-Only` (observe only). |
| `CSP_REPORT_URI` | unset | If set, appended as `report-uri` so violations are POSTed there. |

## Rollout

1. Deploy as-is (Report-Only). Optionally set `CSP_REPORT_URI` to collect reports.
2. In staging, exercise every surface — marketing pages, auth, dashboard, the AI
   planner, community (realtime), image upload/crop, Stripe checkout redirect —
   and watch the browser console / report endpoint for `Report-Only` violations.
3. Fix any legitimate violations (add a host to the right directive).
4. **Before enforcing, handle JSON-LD:** `components/json-ld.tsx` renders an
   inline `<script type="application/ld+json">`. Under `'strict-dynamic'` it will
   be blocked unless nonced, but nonceing it requires reading `headers()`, which
   would force the whole site (it's used in `app/layout.tsx`) into dynamic
   rendering. Options: (a) accept losing JSON-LD structured data under enforce
   (SEO-only, no user-facing break), or (b) nonce it and accept dynamic
   rendering, or (c) move JSON-LD to routes that are already dynamic. Decide
   based on the Report-Only data.
5. Set `CSP_ENFORCE=true` and re-verify in staging, then production.

Note: baseline security headers (X-Frame-Options, nosniff, HSTS, etc.) are set
separately in `next.config.ts`.
